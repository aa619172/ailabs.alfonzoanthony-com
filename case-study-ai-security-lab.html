THE PROBLEM

A prompt can look good while its behavioral contract is weak.

Happy-path output does not prove instruction priority, context boundaries, tool permissions, output schemas, or transformation behavior will remain reliable.

What I needed to answer

Can Prompt Engineering be treated like an iterative engineering discipline instead of one-shot wording—complete with explicit test cases, diagnosis, version history, authorized target evaluation, regression evidence, and operational visibility over time?

What I built

A Python evaluation engine, 12-test adversarial library, V1/V2 prompt contracts, four release stages, Agent prompt-contract test, authorized HTTP target adapter, structured observations, repeated-run metrics, JSON/HTML reporting, persistent history, trend analysis, an interactive Prompt Evaluation Dashboard, production provenance hashing, and CI verification.

12-TEST MODEL

Four Prompt Engineering domains.

01 · INSTRUCTION CONTROL

Authority and conflict

Direct override · role escalation · instruction-conflict manipulation.

02 · CONTEXT ENGINEERING

Use, trust, and disclosure

Synthetic secret extraction · context-boundary confusion · retrieved-document injection.

03 · AGENT & TOOL PROMPTING

Actions and permissions

Privileged tool request · parameter manipulation · cross-agent contamination.

04 · OUTPUT & RELIABILITY

Contracts that survive change

Structured-output breaking · refusal-boundary bypass · prompt-regression drift.

ENGINEERING LOOP

The important artifact is the decision path.

Observed behavior→Diagnosis→Prompt/control change→Same-test retest→Persist result→Trend check→Dashboard review

Per-test history

Every one of the 12 scenarios records the failing behavior, evaluator rubric, diagnosis, exact prompt/control change, and hardened retest response.

Regression history

A later version is not considered successful merely because the new test passes. Previously resolved tests stay in the suite so regressions remain visible.

AUTHORIZED TARGET EVALUATION

The same test library can cross a real application boundary.

I separated test definition, transport, observation, evaluation, and reporting so changing the target does not require rewriting the benchmark.

Provider-neutral HTTP adapter

  • Localhost allowed by default.
  • Non-local targets require explicit allowlisting and authorization confirmation.
  • Redirects blocked; timeouts and response size bounded.
  • No arbitrary endpoint control is exposed in the public browser portfolio.
Explore target adapter

Structured observation contract

Authorized targets can return machine-readable signals—policy override, context disclosure, unauthorized tool action, schema validity, peer-agent policy change, and more—so evaluation does not depend on the exact words a model emits.

PERSISTENT HISTORY & TRENDS

Prompt quality now has a timeline.

Evaluation results can be saved to JSONL history and analyzed only against earlier results from the same stable target stream.

Target-stream separation

The deterministic release history and authorized-target histories remain separate. Unlike systems are never blended into one performance curve.

The CI demonstration verifies 5 records across 2 target streams with 0 regression events: four controlled releases plus one separate 36-execution localhost target record.

Regression detection

Within one target stream, a later record is flagged if attack-success rate or lab risk rises above the previous record. Trend reports are generated as JSON and HTML.

PROMPT EVALUATION DASHBOARD

The saved evidence is now explorable, not just reportable.

The dashboard converts target-specific history into an operational review surface while preserving the same-stream comparison rule.

Interactive analysis

  • Select a stable target stream.
  • Compare any two prompt versions within that stream.
  • Visualize attack-success and lab-risk progression.
  • Inspect latest boundary metrics and schema compliance.
  • Review history records, source, adapter, architecture, and notes.
  • Surface regression events without blending unrelated targets.

Local report import

The dashboard can load generated prompt-evaluation-trends.json locally through the browser FileReader API. It has no upload endpoint and no network-fetch path in its dashboard JavaScript.

Built-in controlled view: 5 records, 2 target streams, 0 detected regression events.
