HOW I ENGINEER PROMPTS

I treat prompting as a system, not a sentence.

My support, UX, and design background improve how I diagnose the problem and communicate the solution, but the portfolio identity is Prompt Engineering.

01

Define the behavior

Start with the outcome and failure boundaries. What should the model do, what should it never do, and what evidence will count as success?

Role · objective · constraints · rubric
02

Engineer the context

Control what the model sees and trusts. Separate instructions from data, scope memory/context, and make tool permissions explicit.

Context · trust · tools · structured inputs
03

Test and refine

Challenge the prompt deliberately. Use normal cases, edge cases, adversarial cases, structured observations, repeated runs, evidence capture, and regression tests.

Evaluate · diagnose · revise · retest
Problem→Prompt contract→Context→Output schema→Evaluation→Failure analysis→Revision→Regression test
