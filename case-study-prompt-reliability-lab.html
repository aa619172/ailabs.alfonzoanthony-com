AI prompt engineering case study

Prompt Reliability Lab

An LLM evaluation and PromptOps prototype that treats prompts like production software: version them, test them against reusable cases, detect regressions, explain failures, and verify corrective prompt changes before deployment.

PythonFastAPIPydanticReactTypeScriptVitePytestPrompt Evaluation

The problem

A prompt can still return valid JSON while behaving incorrectly. Small instruction changes may reduce accuracy, introduce unsafe claims, or violate downstream requirements without producing an obvious application error. Prompt Reliability Lab was built to make those behavioral regressions measurable instead of relying on subjective prompt review.

What I built

  • Prompt registry with explicit version history and editable system prompts.
  • Reusable test cases with expected intent, required terms, forbidden terms, and JSON validation.
  • Automated evaluation scoring for behavioral and structural requirements.
  • A/B prompt comparison with winner selection, score deltas, and regression detection.
  • Prompt Workbench for loading prior versions, editing prompts, and creating new versions.
  • React + TypeScript dashboard connected to a FastAPI evaluation backend.
  • Pytest coverage for API flow and regression detection.

Why this matters

Prompt engineering becomes more reliable when prompts are treated as versioned software artifacts instead of one-off text. The lab separates prompt authoring from evaluation so a change can be measured against the same test suite before it is considered ready for deployment.

Regression experiment

I seeded a customer-support routing prompt with a stable Version 1 and then created an intentionally degraded Version 2 containing an instruction that allowed refund guessing. Both versions continued to produce valid JSON, but Version 2 began generating the prohibited phrase “guaranteed a refund.” The evaluation engine scored Version 1 at 100 and Version 2 at 75, identified Version 1 as the winner, and reported a 25-point regression.

Corrective prompt workflow

Using the Prompt Workbench, I rewrote the degraded prompt to explicitly prohibit invented refunds, credits, cancellations, or unverified outcomes while preserving structured JSON output and classification behavior. That correction became Version 3. Comparing Version 2 against Version 3 produced a 25-point improvement, removed the forbidden-output failure, and restored a 100 reliability score.

What the result demonstrates

The project demonstrates prompt versioning, regression testing, explainable evaluation criteria, structured-output validation, policy-aware prompt refinement, API design, React/TypeScript frontend development, and an iterative test → diagnose → rewrite → verify engineering loop.

Architecture

The current portfolio demo uses a deterministic local model provider so the same prompt behavior can be reproduced without API costs or model drift. The provider layer is intentionally abstracted so real model adapters can be added later while retaining the same registry, test cases, evaluation engine, and comparison workflow.

Portfolio scope

This is a working PromptOps prototype, not a claim of a production enterprise evaluation platform. The current demo uses deterministic local responses for repeatable testing. Prompt versioning, test-case evaluation, scoring, regression detection, comparison APIs, corrective prompt creation, automated tests, and the dashboard are working software. Real-model providers and broader evaluation datasets are planned next.
