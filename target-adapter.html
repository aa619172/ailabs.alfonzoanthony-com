ARCHITECTURE

Transport changes. The evaluation contract does not.

The point is to compare prompt behavior without rewriting the benchmark every time the target changes.

12-test library→Prompt contract→Authorized target adapter→Owned AI application→Structured observations→Evaluator→Metrics + report
01 · Test definition

One source of truth

The attack ID, prompt objective, evaluator rubric, severity, diagnosis, and prompt-engineering skill remain the same whether the target is simulated or networked.

02 · Target boundary

Provider-neutral HTTP

The adapter sends the attack prompt plus the selected prompt contract to an authorized endpoint and captures the application response.

03 · Evaluation

Structured first

Real integrations can return machine-readable observations so evaluation does not depend on whether a model happened to use a particular phrase.

STRUCTURED OBSERVATION CONTRACT

Measure behavior, not keywords.

Text-marker scoring remains only as a compatibility fallback for the deterministic simulator. Authorized targets can supply explicit observations.

REPEATED-RUN METRICS

One response is not enough for a non-deterministic model.

The adapter can repeat the same 12-test suite up to 10 times and aggregate behavior for a specific prompt version.

Attack Success RateSuccessful adversarial outcomes ÷ total executions
Context Leakage RateFailures across the three context-engineering tests
Tool Boundary Violation RateFailures across agent/tool tests
Schema ComplianceCompliance rate for required structured output
Output Reliability Failure RateFailures across schema, refusal, and regression-drift tests

These metrics describe the controlled test set and the selected prompt version. They are not universal model-security scores.
PERSISTENT HISTORY

A captured target result can become a versioned trend record.

The lab persists target label, prompt version, run/execution counts, attack-success rate, risk, boundary metrics, and schema compliance in JSONL history.

TARGET-SPECIFIC TRENDS

Regression detection stays inside the same target stream.

Controlled simulator releases and authorized-target runs are never blended into one performance line. A regression is flagged only when a later record for the same stable target label increases attack-success rate or lab risk.

SAFETY GATE

Network access is intentionally constrained.

The public browser portfolio does not expose a field for arbitrary targets. Networked evaluation lives in the Python lab.

Default behavior

  • localhost, 127.0.0.1, and ::1 allowed by default
  • redirects blocked
  • timeouts capped
  • response size bounded
  • no credentials stored by the adapter

Non-local target

  • hostname must be explicitly allowlisted
  • operator must explicitly confirm authorization
  • the adapter is intended only for owned or authorized systems
  • results are scoped to the configured target and test set

PROMPT ENGINEERING STORY

I did not change the test because the target changed.

I separated prompt-test definition, transport, observation, evaluation, reporting, and history. That makes it possible to compare prompt versions over time while keeping each target stream visible and methodologically separate.
